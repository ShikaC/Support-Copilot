# ADR-0001：先恢复理解，再扩展 AI 能力

状态：已采用
日期：2026-09-04

## 背景

Support Copilot 同时包含 React、Java、Python、数据库、RAG、人工审核、权限和 Pilot 运维边界。当前工作树包含未提交的 Pilot 与容器改动，历史路线文档的阶段描述也不完全一致。仓库没有明确的 OpenRAG 项目、版本或接口约定。

## 决策

在作者能够用自己的话说明一次分析请求的主链路和关键失败语义前：

- 不新增非阻塞业务功能。
- 不接入 OpenRAG、第二套 RAG 流程或新基础设施。
- 先以当前代码、明确 Git SHA、测试输出和运行记录区分已实现、已验证、当前工作区改动及 blocked/partial。
- 若未来评估 OpenRAG，优先放在 Python 知识检索或索引 Adapter；React、Java 业务 API、工单状态、审核、权限和审计契约保持稳定。

## 原因与后果

这样可以避免把历史验证误当成当前工作区证据，也避免为了技术名词扩展尚未稳定的主链路。短期内新增功能速度降低；长期可让每个修改都能被作者解释、复核和回滚。

## 重新评估条件

当固定 mock/live 评估基线、无证据安全率、引用正确性和权限过滤规则稳定，并且 OpenRAG 的具体身份和引入指标已确认时，重新评估本决策。
