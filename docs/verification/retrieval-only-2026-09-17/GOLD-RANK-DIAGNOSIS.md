# gold 全库排名诊断：未命中是排序问题，不是召回问题（2026-09-17）

> 结论：3 道未命中题的 gold 片段**并没有落在检索不到的位置**，它们在全库 1564 个片段中排名第 **4、6、6**；其中一题与第 3 名的分数差只有 **0.0004**。
>
> 全部 11 题可评估题目的 gold 都进入前 6。也就是说：向量检索已经把目标召回到很靠前的位置，**瓶颈在排序精度与 `top_k=3` 的截断**，而不是"检索找不到答案"。
>
> 本诊断零外部调用，只使用上一次检索-only 运行已缓存的 query 向量与现有 artifact 矩阵。

## 1. 与 `retrieval-eval.mjs` 的口径差异

两个数字回答不同问题，不能互相替代：

| 口径 | 问的问题 | 本次结果 |
| --- | --- | --- |
| `retrieval-eval.mjs` 的 gold@k | **返回给模型的候选**里有没有 gold | gold@1 6/11、gold@3 8/11 |
| 本诊断的全库排名 | gold 片段在 **1564 个片段**里排第几 | recall@1 6/11、recall@4 9/11、recall@6 11/11 |

`top_k=3` 意味着只有 3 条候选能进入模型上下文，所以只要 gold 排在第 4 名及以后，对下游就是"没检索到"。本诊断要回答的是：这些题到底是排第 4 名还是排第 400 名——两者需要完全不同的修复方向。

## 3. 三点含义

1. **上限很高**：11 题的 gold 全部进入前 6，说明 embedding 与当前切片足以把正确文档召回。任何"换 embedding 模型"的动作都缺少证据支撑。
2. **真正要修的是排序**：把 gold 从第 4–6 名提到前 3，是重排（rerank）或混合检索（BM25 + 向量融合）能直接作用的区间。前几名的分数高度密集（例如 0.8146 / 0.8125 / 0.7975，或 0.7099 / 0.7069 / 0.7011），说明纯向量相似度在这个区间区分力不足。
3. **`top_k` 是成本决策，不是质量修复**：把 `top_k` 从 3 提到 6 会让 gold@3 指标看起来变好，但那只是把更多候选塞进上下文，会增加 token 成本并稀释证据。它可以作为独立议题讨论，但不应被记作"检索质量改进"。

## 4. 一个待验证的相关性观察

未命中的 3 题，gold 文档分别只有 **1、2、2** 个片段；而 8 个片段的题排名第 1。11 题的样本量不足以支持结论，但它提示：**细粒度切片可能让"答案只出现在一个片段里"的题目更难被匹配到**。如果后续要验证，应固定 query 与向量，只变切片方式，再比较同一批题目的 gold 排名。

## 5. 复现方法

零外部调用。运行零依赖的正式工具（9 项契约测试）：

```bash
cd services/support-copilot-ai
.venv/bin/python -m evaluation.gold_rank \
  --vectors docs/verification/retrieval-only-2026-09-17/query-vectors.json \
  --json docs/verification/retrieval-only-2026-09-17/gold-rank.json
```

工具读取缓存 query 向量与 artifact `matrix.npy`，用 `cases.json` 的 `source.document_id` 经 `corpus.json` 的 `source_uri` anchor 映射到 `document_id`，取该文档全部片段作为 gold，输出 gold 最佳分数、全库排名与前 3 名分数。

注意：`query-vectors.json` 不入库（341KB），需要先按 [README](README.md) 的步骤重跑检索-only 运行才能复现本诊断。

## 6. 限制

- 全库排名是**诊断口径**，不是产品指标；产品上看的是返回候选（见 `retrieval-eval.mjs`）。
- 余弦相似度是唯一排序依据，未包含任何重排或融合；排名只说明"纯向量检索"的表现。
- 11 题、development 切片、归档语料。这些数字不能外推到真实客服知识库，也不能当作模型回答质量。
- gold 是文档级标注，命中不代表片段包含完整答案。
