# 公开问题 RAG 真实调用实验

2026-09-10 已完成第一轮真实调用：20 道公开问题，45 次生成请求，37 次结构合格返回、8 次读取超时。**这是公开数据上的组件实验，尚不是经过人工审核的质量基线；准确率保持未评测。**

直接查看 [逐题回答与证据](RESULTS.md)、[机器汇总](run-1/summary.json)、[原始运行配置](run-1/manifest.json) 和 [逐次运行日志](run-1.log)。所有失败保留，没有自动重试、删除失败或择优取样。

## 数据与实际执行范围

- 问题来自公开 GitHub CLI Issues，48 条候选中有目的地选取 20 条，使用英文归纳提问；不是随机抽样，也不是内部客服原始工单。来源与筛选记录见 [数据材料](../public-rag-pilot-2026-09-10/README.md)。
- 官方文档来自已安装 GitHub CLI 2.100.0 的帮助输出。冻结 107 份文本，排除重复的聚合 reference 后，106 份进入检索，切为 249 块；每块 24 行、步长 20 行，保留原始行号。第一轮未移除通用页脚。
- 249 文档块与 20 问题共 269 条真实向量，1024 维，分 17 批生成，耗时约 3.22 秒；模型为 Qwen/Qwen3-Embedding-0.6B。
- 生成调用配置模型名为 gpt-5.6-luna，Chat Completions 结构化解析；复用项目现有 Embedding 和生成 provider、提示词、脱敏、输出契约。这里的名称是调用配置，不能独立证明网关背后的模型身份。
- 两种检索各跑 20 题：BM25 与余弦向量检索，最多提供 3 块。另对 5 题直接提供 AI 预标注所指向的文档原文作排查对照；未将候选答案、评分规则放入模型上下文。对照不是人工 gold，实际文本长度也与检索组不同。
- 本实验在独立目录运行，未经过 Java 工单状态、审核、Python 风险策略和最终回复约束，未替换工作台知识库或质量页当前的合成回归报告。因此不能代表完整线上 RAG 或最终客服回复效果。

| 方案 | 请求 | 结构合格返回 | 读取超时 | 生成 p50 | 生成 p95 | 纯导航证据位置 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |

结构合格仅检查解析与引用序号，**不是答案正确**。p50/p95 为 nearest-rank，包含失败请求耗时，只统计生成，不包含远端向量化；不是用户端到端延迟。纯导航按完整片段是否仅包含固定 help/manual/exit-codes/accessibility 导航行和空行检查，按实际提供位置计数，不去重，不等于召回率。

37 份返回中，模型自报证据充分 22 份、不足 15 份；这些自评没有计入正确率。8 次失败均保留 `APITimeoutError / ReadTimeout`，说明客户端等待响应超时，不能据此确定网关或模型服务内部根因。失败分布于三组，样本小且串行，不能将组间超时差异归因于检索算法。

有 usage 的请求共记录输入 58,332、输出 17,102 tokens。失败请求与 Embedding 缺少 token usage，不补为零；缺少实际网关价格，费用未核算。

## 对原文的 AI 初审：可以定位什么问题

以下为协作者核对输出和文档后的定性发现，**不是人工审核标签或完整逐题正确性评分**。

1. **检索噪声：#9457 续传下载。** 向量前三条中的前两条为通用页脚，第三条只含示例与导航；关键下载 flags 未进入上下文。BM25 与候选证据对照都取得 flags，能够解释当前文档没有列出 resume。证据：[向量原始记录](run-1/trials/gh-public-9457-vector.json)、[对照](run-1/trials/gh-public-9457-proposed_evidence.json)。不能用当前帮助证明旧版 2.49.2 的完整行为。
2. **有用检索：#2751 多附件发布。** BM25 没有提供 `gh release create` 用法，模型拒答；向量组检索到 `[<filename>... | <pattern>...]` 并提供多文件示例。这证明此题有实质区别，不能外推向量整体优于关键词。证据：[BM25](run-1/trials/gh-public-2751-bm25.json)、[向量](run-1/trials/gh-public-2751-vector.json)。
3. **超出证据的肯定：#9763 非 fork 仓库 PR。** BM25 回答以 Yes 开头，依据 `--head` 跳过自动 fork/push，推导出可以不建立 fork 关系。给定原文只说明 CLI 行为，没有证明任意无 fork 关系仓库都可创建 PR；向量组对该限制更谨慎。问题在证据蕴含，不是引用序号。证据：[BM25 原话](run-1/trials/gh-public-9763-bm25.json)、[冻结帮助 L5–12](../public-rag-pilot-2026-09-10/corpus/gh_pr_create.txt)。
4. **检索正确仍可能生成越界：#5147 升级失败。** 直接提供升级命令与 flags 后，模型称重试 `--force` 是“documented next step”。帮助只列出参数，没有把它规定为 status-1 故障恢复方案，也没有验证 2.4.0 的故障原因。此题更适合说明已知用法，并索取脱敏错误输出、扩展名和复现条件。证据：[对照原话](run-1/trials/gh-public-5147-proposed_evidence.json)、[冻结帮助](../public-rag-pilot-2026-09-10/corpus/gh_extension_upgrade.txt)。
5. **可直接核对的正例：#5100 布尔开关。** 三组均返回 `--enable-issues=false`，与文档说明一致；#1331 的 BM25 和证据对照也给出了 `--title` 与 `--body-file` 组合，但向量组超时。这里只记录具体观察，不把少量正例冒充总体准确率。

## 后续最小修复与验收

第一步应修隔离实验的文档清洗与分块：去掉通用导航，保留来源行号；对固定文档检查不再生成纯导航块。使用已冻结问题和文档，重新构建单独索引并输出所有检索排名，先离线核对噪声指标和原有相关片段是否丢失，再决定必要的生成对照；保留本轮作为 before。

随后处理证据蕴含：把“文档存在某参数”与“该参数能解决当前故障”分开评审；用上述失败案例验证提示词或最终回复策略。不能用减少回答、统一拒答或弱化评分掩盖问题。超时需结合供应端/网关日志定位，增加超时或重试属于预算改变，必须作为新实验条件明确记录。

要得到可信准确率，还需按完整语料核实每题是否可回答、标出独立参考证据和答案要点，冻结未用于调参的测试集并完成人工审核。当前 20 题已用于开发诊断，不能再冒充盲测；可以用它们形成开发基线，再从未使用问题构建独立测试集。
