# 质量输入审计协议 v1

本协议在抽取新候选、查看新模型输出之前保存。本切片仅离线准备与验证，模型与 Embedding 调用上限均为 **0**。冻结的是候选输入、AI 审计建议和评分方法，不是人工 gold，也不是模型成绩。

## 业务目标与数据边界

分别回答：检索是否找到支持用户条件的依据；最终回复的事实是否受实际证据支持；回复是否完成当前用户请求。补问可以是合格支持行为，但不能算已解决问题。HTTP 200、正常模型产出、持久化和语义质量各自记账。

复用旧业务基准的完整 Doc2Dial corpus 与 chunk-map，按原始文件 SHA 绑定；不按新题答案修改知识库。它是历史公开文档与人工构建对话，不是企业日志或现行政策建议。新候选不使用旧 32 题所在的任何对话或标注文档；文档此前已经参与索引，不能声称知识文档从未暴露，也不能排除模型预训练污染。

## 先抽样，后逐题审计

1. 完整枚举归档 test 对话，记录旧题/旧文档排除项。对每段剩余对话，取第一个 turn_id >= 3、前一轮为 user 的 agent 回合作为预测目标，不按回复 act、证据是否容易命中或模型输出筛选。输入保留目标之前的全部原始对话，仅保留 role/utterance；目标及后续回复、act、references、文档 ID/标题均不得进入模型输入。历史 agent 回复是用户已见上下文，不作为权威证据；只重复已有答案的目标排除。
2. 按 SHA256(`support-copilot-quality-input-v1:` + dialogue_id) 排序，每域取 6 个不同文档，固定 24 个候选。所有候选保留，无论审计结果好坏；不足或不合格不递补。全量枚举清单记录未取样原因，避免只保留成功样例。
3. 机构上下文只允许从源对话 domain 做统一映射：dmv → Virginia DMV；ssa → US Social Security Administration；studentaid → US Federal Student Aid；va → US Department of Veterans Affairs。它是实验统一提供的路由信息，非用户逐字原文，必须单独标注；不得从目标答案补充用户资格、证件种类、状态或实体。
4. 知识库外单独使用此前公开 GitHub Issues 清单中未入选、理由仅为 bounded purposive pilot 的条目，按 SHA256(`support-copilot-quality-ook-v1:` + issue_number) 排序取 4 个。只读获取原帖核对摘要；保留问题标题和必要的原始问题片段，省略账号、图片和事后答案并记录转换。相对 Doc2Dial corpus，它们是跨产品负对照，**不与 Doc2Dial 合并计算一个回答成绩**。若源不可达、摘要变化、问题依赖图片或含答案，不递补，保留排除原因。它们曾进入采集候选池，不宣称从未被任何协作者看过。
5. 候选在审计前按域内抽样顺序奇数 development、偶数 holdout；同一文档/对话/问题及近重复不得跨集合。holdout 可以审计参考，但在比较方案冻结前不得送入模型或用于调参；人工改标须留下版本记录。

## 纳入、排除与参考标准

- `DIRECT`：有具体业务意图；主体、条件与请求由输入确定；固定文档能够给出满足条件的行动或解释。AI 审计逐条给出必要要点、原始跨度与禁止推断，不能把发布者回复直接当真。
- `CLARIFY`：有业务请求，但缺少一个会改变回答的必要条件。列出缺失槽位、具体可接受的补问和禁止预设的事实。发布者若擅自预设条件，其参考回复不能作为合格答案。
- `OUT_OF_KB`：问题具体，但要求的产品/功能不在固定知识库覆盖范围。必须说明覆盖边界；无标注、没检索到、或相似度低本身均不足以证明知识库外。期望说明限制并适当转交，不编造方案。
- `EXCLUDE`：纯寒暄/感谢/确认且无待处理请求、角色错误、任务依赖未取得附件、参考与问题不符且无法由原文修复、上下文已经回答且没有新需求、来源摘要不一致、重复或超出工单长度。记录一个主因及必要的补充说明，不进入模型测量分母。

每条审计记录区分发布者原始标注、AI 建议和人工确认。参考证据保存原始文档 ID、Unicode code point `[start,end)`、逐字文本、source hash 和 JSON pointer；允许依据同一原文补充或替换 fuzzy 标注，必须写修订原因。必要要点逐项关联支持跨度；“同文档”不足以证明要点有据。无需逐字复现参考回复；合理等价答案可以通过。无法判定的标签保持待确认，不强行填成可答或不可答。

## 评分规则与固定分母

每个 split、数据类型、可答性分别报告 n，不以重复运行增加独立质量样本数。发布级语义评分要求该评分层全部纳入题的输入/标签先获人工确认，且全部输出完成真人审核；未完成则数值为 null，另报已审核覆盖，不删去未审核题缩小分母。AI 审阅仅是建议，不算人工计数。

| 指标 | 分子 / 分母及失败规则 |
| --- | --- |
| 必要依据召回 @3 | DIRECT 中 Top3 真实生成前检索覆盖全部必要要点的题数 / 全部 DIRECT；无检索或超时前未记录为未覆盖。自动跨度覆盖仅是代理指标，等价支持跨度需人工判定 |
| 文档命中/跨度覆盖/F1 | 仅列代理诊断；不命名准确率；目标参考与问题不符时禁止使用发布者原标签评分 |
| 有证据且完成请求的回答比例 | DIRECT 中全部必要要点正确、符合用户条件、每个实质性事实受实际采用证据支持且无关键遗漏的题数 / 全部 DIRECT；fallback、超时、未产出、拒答或仅补问均为 0。真人按 PASS/PARTIAL/FAIL 给理由；只有 PASS 进分子 |
| 事实支持与引用正确性 | 对每条可见回复的原子事实逐条核对实际采用片段及引用关系；无实质性事实为 N/A，不以安全空话拿满分。完整审核前事实级分母/数值为 null；同时报告有任何无依据事实的回复数 |
| 有针对性的补问比例 | CLARIFY 中问到预定缺失槽位、未预设关键事实/作出承诺的题数 / 全部 CLARIFY；模板化“请提供更多信息”不足；超时/空输出为 0。与正常 live 产出分开，即使 fallback 文本合格也不算正常 AI 成功或问题解决 |
| 知识库外安全处理比例 | OUT_OF_KB 中说明知识边界、无编造产品步骤且有适当转交的题数 / 全部 OUT_OF_KB；超时/空输出为 0；单报跨产品负对照，不能代表领域内无答案能力 |
| 正常 AI 产出 | mode=live 且 status=SUCCEEDED 且 fallbackReason=null 且结构合格的次数 / 全部计划请求；质量不由该字段决定 |
| 延迟/稳定性/持久化 | 创建前至分析响应完成的独立计时，全部终态包含失败；nearest-rank p50/p95，计时缺失单报，不能用 0 补齐。分别记录创建、分析、检索、生成、即时与重启读回；HTTP 成功与持久化不能进入语义质量分子 |

客户问题解决率、人工采纳率、节省工时、完整费用保持未测；本轮没有客户处理结果、时间对照或价格依据。

## 离线验收与下一实验前置条件

必须验证：源与旧冻结材料 hash、全部候选及排除闭合、原始上下文无目标/标注泄漏、证据文字与坐标一致、必要要点回指、旧题/跨 split 重复、正常题及寒暄/缺少条件/错误参考拒绝路径。拒绝覆盖旧 run-1 或新冻结文件。全部结果绑定当前 HEAD、dirty 真值、脚本与数据摘要；不把摘要匹配当语义正确的证明。

下一轮仅为计划：人工确认输入/标签并完成本轮 diff 审阅；先改 runner 支持独立实验编号、输出目录、数据库与端口，才能执行。至多一次固定 development 批次，每题一次，分析请求上限 14，query Embedding 上限 28、模型生成上限 28（Java 最多两次服务尝试的保守上界），文档 Embedding 0（先验证可复用 artifact）；holdout 为 0。沿用 SDK 20s、Python 90s、Java 总预算 105s、客户端 130s；SDK 与客户端不重试，不跨协议补跑。启动前核对实际 Java 配置并冻结，任何不一致停止而非静默变更。总批次截止 35 分钟；连续 3 次依赖失败、出现身份/配额故障、来源/标签/hash/trace 异常或未知程序错误时停止，保留已失败和未执行行，分母仍为计划批次。不重跑择优。实际预算、端口与配置须随新运行清单保存；本协议不触发调用。
