# 优化 16：记录每条评估案例使用的模型

## V1 原来的问题

优化 15 已经能列出一批评估中出现过哪些模型，但单条案例结果仍然没有模型名称。

当同一批次出现模型 X 和模型 Y 时，报告只能知道两个模型都出现过，不能回答：

```text
某条错误分类是谁产生的？
某条慢案例使用了哪个模型？
三条慢案例是否全部来自模型 Y？
```

## 本次如何修改

`CaseEvaluationResult` 新增 `model_name` 字段。构建单条评估结果时，从与该案例对应的 `AnalyzeResponse.model_name` 直接复制实际模型名称。

数据关系现在是：

```text
案例 ID -> 模型名称 -> 分类与检索结果 -> 耗时 -> 失败原因
```

## 相对 V1 的改进

```text
V1：
只有批次级模型集合
-> 无法把具体结果归因到具体模型

优化后：
每条案例保存自己的模型名称
-> 可以定位某条错误或慢案例来自哪个模型
-> 为以后按模型分别计算指标提供原始数据
```

## 自动化测试

测试模拟同一批次混用两个模型：

- 第一条响应使用 `model-x`。
- 第二条及后续响应使用 `model-y`。
- 报告必须同时保存全局模型集合和每条案例的实际模型归属。

## 当前边界

现在已有按模型统计所需的案例级原始数据，但报告尚未自动生成每个模型各自的准确率、慢案例数量和慢案例比例。是否增加这些聚合指标，应根据真实的多模型评估需求决定。
