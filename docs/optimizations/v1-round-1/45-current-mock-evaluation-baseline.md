# 优化 45：固化当前 Mock 评估基线

## 业务问题

项目已有固定评估集和自动报告能力，但报告目录默认被 Git 忽略。旧报告只留在本机，README 也没有指向一份绑定当前提交、可供面试复核的结果，因此“评估脚本存在”和“当前版本实际通过评估”仍是两件不同的事。

## 改进方案

在干净提交 `d0989834bab0d76b3966e5288e0e75d7d37f2815` 上重新执行 Python 全量测试和固定 mock 评估，检查自动生成的 JSON、Markdown 报告后，将不含工单正文的指标摘要固化到：

```text
docs/verification/mock-evaluation-2026-08-24.md
```

快照记录提交 SHA、工作区状态、环境版本、数据集与知识库 SHA-256、分析配置、指标、门槛和运行命令。README、评估说明和路线图统一链接这份证据，避免后续手工复制一组没有来源的指标。

## 当前验证

- `.venv/bin/pytest -q`：53 条 Python 测试通过。
- `.venv/bin/python -m evaluation.run_mock_evaluation`：退出码 `0`。
- 18 条固定模拟工单全部通过，失败案例为 0。
- 分类、优先级、升级、Hit@3、MRR、引用、无证据安全和回复约束指标均达到既有门槛。
- 报告中的 Git SHA、数据集哈希和知识库哈希与本次运行输入一致。
- 固化快照不包含 API Key、授权头、真实客户信息或逐案例工单正文。

## 能力边界

该基线只验证本地确定性 mock 工作流，不能证明正式模型质量、真实 Embedding 效果或生产性能。1.000 指标只适用于当前 18 条人工维护的固定案例，不能表述为通用准确率。真实 live RAG 仍需正式 API 成功调用和脱敏记录。
