# 优化 58：扩充评估集并增加检索证据门禁

## 业务问题

原有评估集只有 18 条案例，mock 检索的固定分数门槛较低，通用问题可能因为中文二元词偶然命中不相关知识。live 向量检索也没有最低相似度门禁，非空向量库会直接返回 Top K，可能把弱相关片段交给生成模型。

## 改进内容

### 评估数据

`evaluation/data/tickets.jsonl` 从 18 条扩充到 31 条，增加了：

- 退款、账号锁定、发票重开、导出任务和席位计费变体。
- 隐私导出与删除的组合请求。
- 英文 SSO 和技术代理输入。
- 通用未知问题、低置信度查询和无证据历史恢复问题。

每条案例继续由人工维护分类、优先级、升级、期望证据 ID 和回复约束，不从系统输出反推标签。

### 检索安全

- mock 检索默认使用 `MOCK_RETRIEVAL_MIN_SCORE=0.25`。
- 已知工单分类会先参与候选门禁，避免同类证据因弱词面分数被错误丢弃。
- live `InMemoryVectorStore` 的分数已确认是余弦相似度。
- live 检索默认使用 `LIVE_RETRIEVAL_MIN_SCORE=0.35`，低于阈值时返回空证据。
- 空证据会沿用现有 `insufficient_evidence` fallback，并在模型调用前阻止生成请求。
- 隐私规则优先于通用数据导出规则，避免“离职员工数据导出并删除”被误分类为普通导出任务。
