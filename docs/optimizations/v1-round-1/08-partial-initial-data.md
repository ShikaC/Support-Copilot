# 优化 08：启动数据支持部分可用

## V1 的问题

应用启动时，React 使用 `Promise.all` 同时请求工单和指标：

```text
工单成功 + 指标失败
    -> Promise.all 整体失败
    -> 丢弃已经成功取得的工单
    -> 页面继续使用全部 Demo 数据
```

这会让一个指标接口的故障影响工单主流程，也可能让用户误以为工单数据也是演示数据。

## 本轮修改

### 1. 使用 `Promise.allSettled`

两个请求仍然并行发出，但结果分别读取：

- 工单请求成功：更新工单列表。
- 指标请求成功：更新指标数据。
- 指标请求失败：指标状态设为不可用，不展示旧的或伪造的数字。
- 两个请求都失败：保留本地演示工单和演示指标，进入完整 Demo 模式。

### 2. 增加 `partial` 服务状态

侧边栏现在可以显示：

```text
业务 API 已连接
部分服务可用
演示数据模式
```

`partial` 表示部分服务可用，不等于整个后端已经健康。

### 3. 缺失指标使用明确空状态

指标卡显示 `--` 和“指标暂不可用”；运营概览和质量评估页面显示说明文字，不使用看起来像真实结果的 Demo 数字。

## 相对 V1 的改进

```text
V1
任一启动接口失败 -> 全部进入 Demo

现在
工单成功 + 指标失败 -> 真实工单可继续处理，指标明确不可用
全部失败         -> 完整 Demo
```

## 当前边界

两个请求虽然同时发出，但它们仍然不是同一个后端快照。如果页面需要保证工单和指标严格来自同一时刻，后续应由 Java 提供统一的初始化接口，或者为指标响应增加明确的统计时间范围。
