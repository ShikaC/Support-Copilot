# Support Copilot 七天面试冲刺

> 开始日期：2026-08-14
>
> 时间预算：每天约 5 小时，共约 35 小时
>
> 阶段目标：形成可运行、可演示、可验证并能用于 AI 应用开发面试的 V1.5 求职版本

## 1. 完成标准

七天结束时，项目应至少具备：

- 新环境能够按照文档启动核心服务。
- Python、Java、React 三条 GitHub CI 在远端实际运行通过。
- 至少一条成功分析和一条失败路径得到跨服务验证。
- RAG、引用、置信度和人工升级能够用固定评估证据解释。
- 一次分析可以通过 `traceId` 和运行记录追踪。
- README、架构图、5 至 8 分钟演示脚本和真实简历表述相互一致。
- 项目作者能用 5 分钟和 15 分钟两种长度讲清项目。

这不代表完成真实生产系统。认证授权、生产数据库、高并发、云部署等未完成能力必须继续明确标注。

## 2. 每日固定节奏

```text
2.5 小时：实现、测试和故障修复
1 小时：理解架构、数据流和技术取舍
1 小时：口头复述和模拟面试
0.5 小时：整理文档、验证证据和遗留问题
```

每个功能批次结束后，用以下模板复述：

```text
问题 -> 风险 -> 修改层 -> 新流程 -> 验证证据 -> 当前限制
```

## 3. 七天执行表

### 第 1 天：远端基线和 CI

目标：让已经完成的改进在 GitHub 上形成真实验证证据。

- 经用户明确授权后推送当前本地提交。
- 观察 Python AI CI、Java API CI、React Web CI 的第一次远程运行。
- 修复仅在 GitHub Linux 环境出现的问题。
- 三条 CI 全部通过后记录运行链接和结果。
- 评估是否能够配置 `master` 分支保护和必需检查。

验收：三条远程 CI 有可查看的绿色运行记录，或阻塞原因被准确记录。

### 第 2 天：可复现启动

目标：证明新环境可以启动，而不是只在当前电脑上运行。

- 核对三个服务的环境变量和启动顺序。
- 增加统一的启动前检查和健康检查。
- 用 mock 模式完成一次完整本地启动。
- 修正 README 中与真实命令不一致的内容。

验收：按照 README 可以启动 React、Java、Python，并看到健康状态。

### 第 3 天：跨服务关键流程

目标：验证真实服务之间能够完成核心业务流程。

- 覆盖一次成功工单分析。
- 覆盖一次版本冲突或 AI 服务失败路径。
- 优先测试可观察结果，不追求大量低价值测试数量。
- 记录请求、响应、数据库结果和页面结果。

验收：至少两条关键业务场景有自动化或可重复运行证据。

### 第 4 天：错误追踪和可观测性

目标：面试时能够解释如何定位一次失败。

- 核对 `traceId` 在 React、Java、Python 之间的传递。
- 统一关键错误分类和日志字段。
- 演练超时、非结构化错误和版本冲突。
- 记录哪些错误进入 fallback，哪些必须暴露为程序错误。

验收：能够从一个 `traceId` 说明请求经过了哪些服务以及为何失败。

### 第 5 天：AI、RAG 和评估证据

目标：证明项目不仅是普通 CRUD 页面。

- 重新运行固定 mock 评估集。
- 核对分类、优先级、升级、检索、引用和高风险降级指标。
- 解释 Top N、Top K、grounded 和 evidence 的业务意义。
- 只有具备 API Key、预算和脱敏条件时才验证 live 模式。

验收：保存可重复的评估报告，并能准确说明指标边界。

### 第 6 天：作品材料

目标：把工程事实整理成面试官可以快速理解的作品。

- 收敛 README 的启动、架构、验证和能力边界。
- 生成架构图和关键流程图。
- 编写 5 至 8 分钟演示脚本。
- 准备只包含真实证据的简历项目描述。
- 准备成功、失败和技术取舍三个 STAR 故事。

验收：陌生读者可以在不阅读全部源码的情况下理解并运行项目。

### 第 7 天：面试演练和发布检查

目标：把“项目完成”转化为“能够讲清楚”。

- 完成一次 5 分钟项目介绍。
- 完成一次 15 分钟深度讲解。
- 回答 React、Java、Python、RAG、事务、CI、测试和限制相关追问。
- 只修复阻碍演示或解释的高优先级问题。
- 核对 Git 状态、CI 状态、文档和演示证据。

验收：项目作者不看逐字稿也能完成核心讲解，并能诚实回答未完成能力。

## 4. 一周内不进入主线

- 完整 OAuth2、RBAC 和多租户。
- Redis、消息队列和 Kubernetes。
- 没有真实条件支撑的高并发压测。
- 大规模 UI 重构和纯装饰性优化。
- 逐行学习全部 React、Java 和 Python 语法。

这些能力可以继续进入成熟项目路线，但不能阻塞本周求职版本。

## 5. 当前第一步

本地已经积累多轮尚未推送的 CI 和测试提交。第 1 天首先需要用户明确授权推送，然后观察 GitHub 上三条工作流的真实结果。远程绿色状态出现前，不能把本地工作流配置描述为已经在 GitHub 验证通过。
